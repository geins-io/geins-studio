# Assets Library — cutover ledger

Single source of truth for everything the **Phase 8 (real-API alignment)** prep adds that is _temporary_, so the mock → `Geins.Media` cutover — and later phase-2 parity — leaves **no dead code**. Every Phase 8 PR that adds temporary scaffolding appends a row here.

Tracking issue: [STU-331](https://linear.app/geins/issue/STU-331). Backend plan: [asset-library-phase-1](https://github.com/geins-io/geins-platform/blob/master/plans/asset-library-phase-1.md).

## How to use this at cutover

```bash
grep -rn "cutover:" app server shared nuxt.config.ts   # every marked temporary site
grep -rn "useAssetCapabilities" app                     # every capability-gating consumer
```

The `// cutover:` marker is a **semantic marker, not an issue reference** (so it's fine under the no-issue-refs-in-comments rule). The grep set and this table must agree — if you add a temporary site, mark it _and_ add a row.

## Dispositions

- **KEEP** — permanent; it _is_ the real API contract. Do nothing.
- **REMOVE@cutover** — delete when the real API replaces the mock.
- **REVISIT@phase2** — becomes inert once phase 2 restores the feature; strip it then.

## Phase-2 parity cleanup (the standing slop risk)

The mock deletion is a single, obvious step. The one thing that quietly rots is the **STU-324 gating**: phase 1 already restored description/alt-text edit + delete (STU-346); once phase 2 restores the rest (tags, channels, replace), the capability checks are inert-but-dead. Rename + folder move already left the matrix with STU-355 rather than sitting there as always-`true` flags — do the same for each remaining flag as phase 2 lands it. When that lands:

1. `grep -rn "useAssetCapabilities"` → remove each consumer's gate (fieldset, `:disabled` bindings, `canDelete` prop + its wiring).
2. Delete `useAssetCapabilities.ts`, `assetCapabilities`, the `AssetCapabilities`/`AssetsBackend` types, and the `assetsBackend` config.
3. `grep -rn "cutover:"` returns nothing → the ledger is discharged.
